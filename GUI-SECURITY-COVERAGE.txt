GUI security coverage review: explicit client operations

Review base: fe1fa38107907e14a132f45b34d589f74488400f
Initial reviewed commit: 9ee709eb5f720b278a992692953604c4f986d557
Follow-up regression tests exercise the working-tree corrections to that commit.

The nine deleted GUI test files contained 189 test functions before parameter
expansion. Their removal cannot all be classified as obsolete approval coverage.
This review did not delete or skip existing tests. It added independent tests for
security behavior still present in the replacement interface.

Removed tests and present coverage

1. test_gui_approvals.py, test_gui_pending_execution.py,
   test_gui_plan_badge.py and test_gui_policies.py
   Approval inspection, attestations, grant creation, arming, approval revisions
   and pending-approval badges have no active replacement action and are obsolete.
   Shared stale-result, busy-action and shutdown safety is still relevant:
   test_gui_model.py and test_gui_timeline.py cover stale/busy action guards;
   test_gui_shutdown_review.py restores main-window close checks both before and
   after a delayed Tunnel shutdown callback. Tests for retired HTTP and launch
   interfaces verify denial rather than converting old requests to execution.

2. test_gui_home_line.py
   Approval-time raw HOME-line retention and its GUI have been retired.
   The serial execute_with_local_probe entry point clears the probe and refuses
   execution. test_home_line_boundary_regressions.py and the rewritten HOME-line
   integration tests retain the no-arming/no-expanded-raw-retention boundary.
   These deleted raw-preview UI controls do not apply to the current GUI.

3. test_gui_device_observation.py and test_gui_restart_observation.py
   Approval disclosure tests are obsolete, but retained metadata, expiry,
   projection and operation/result integrity still apply. Existing device and
   restart observation integration tests retain current-principal read checks,
   bounded/redacted reports, original cache deadlines, same-device close and
   restart-without-replay checks. Independent test_gui_retention_review.py covers
   strict metadata fields, no raw/unknown extension projection, fixed expiry,
   same-epoch disappearance/reappearance, epoch changes, same-hash metadata
   consistency, capacity exhaustion and exact operation/result/reset flags.

4. test_gui_job_cancel.py
   Cancellation is still active. test_gui_timeline.py covers exact-target
   selection, busy-action guards, wrong identity acknowledgements and lack of
   ownership release. test_gui_cancel_receipt_review.py restores the known-state
   and strict-boolean receipt checks, missing-flag rejection, the original
   ten-second dispatch window, malformed-target rejection before network access,
   fixed transport errors and no automatic retry on duplicate/uncertain outcomes.
   A documented intentional difference is that a fresh explicit refresh may
   permit a new manual cancellation click. The old per-job cancellation latch
   prohibited this even after a fresh refresh. Neither path retries automatically.

5. test_gui_timeline_state.py
   Approval/decision state is obsolete. Existing test_gui_images.py retains PNG
   size, dimensions, signature, chunk CRC, raster/decompression, hash and exact
   recipient validation. test_gui_timeline.py retains identity/epoch binding,
   preview expiry, stale-result rejection, worker-thread boundaries and absence
   of automatic execution/recapture. test_gui_model.py retains queue ownership,
   idle release guards, local URL/auth-header safety and fixed error messages.
   test_image_delivery.py retains same-principal current-read authorization,
   bounded lifetime, eviction, restart disposal and per-request revalidation.

Concrete regressions found and corrected by the follow-up

- Snapshot replacement had removed the previous minimum-expiry clamp. Identical
  image/report refreshes extended a local deadline from 1200 to 1300. Corrections
  retain the earliest deadline across same-epoch refresh and disappearance.
- Observation parsing had lost the exact firmware_observe/result and
  restart_and_observe/result pairing. Corrections restore the pair and enforce
  the actual broker reset/gap flag invariants. The latter flag relationship is
  additional defense in depth; the old GUI checked flag types but not all pairs.
- Cancel acknowledgement parsing had stopped validating the state enum and
  stop_requested boolean, and delayed dispatch no longer had the old time bound.
  Corrections restore these checks without executing or releasing device work.

The new retention identity cache stores only deadlines and metadata digests,
never pixels or raw device text. It is bounded to 10000 identities, matching the
broker job-history ceiling. Capacity exhaustion rejects refresh rather than
evicting a live deadline and allowing that identity to acquire a later expiry.
Changing the broker epoch resets this identity history and clears old previews.

Validation limits

The review used real official filelock 4.0.9 and pytest-asyncio 1.4.0 source with
Git blob hashes verified, together with the installed Python dependencies. This
is supplemental host evidence, not a completed uv sync --frozen validation.
No hardware, deployment, restart, merge or privilege change was performed.
The retained GUI/image/authentication selection produced 225 passes and five
HTTP fixture errors: KeyRegistry rejected this execution environment's root
directory owner UID. No security check or fixture was weakened to bypass it.
That result is not a claim that the HTTP tests passed, and the full suite,
native Windows rendering, packaging and external CI remain separate evidence.
